# Codex context picker and refresh

New project opens the saved Codex project picker. Search and select one or more projects, optionally expand them to select chats, then choose Add selected projects. Existing Research Compass projects are reopened with their saved work. Create a project manually opens the standalone name and description form.

Link Codex context shows projects as accordions. Select the parent reference, selected child chats, or both. Selecting a project does not silently select all its chats. Chats keep explicit source project membership, including after linking. Unassigned chats have a separate group. The picker saves references and list metadata; it does not transfer files or chat messages.

The private Site stores the latest complete metadata catalog in D1. The catalog remains browsable with the local computer off. Refresh from Codex queues a fresh metadata read on the source computer. The picker polls the request receipt and reloads only after an actual upload succeeds. It retains the saved list after a failure and displays a waiting message when the computer is unavailable. Requests expire after 15 minutes; request another refresh after the computer is available if needed. Last synced is shown in Eastern time.

A per-user Windows task, Research Compass - Codex catalog sync, runs at sign-in and hourly while the user remains signed in. The separate Research Compass - Manual refresh listener starts at sign-in and checks for requested refreshes every five seconds while running. Both use the read-only Codex app-server project/list and thread/list APIs and explicit desktop membership metadata. They never use folder similarity or transcript APIs. A failed source read or upload retains the previous hosted catalog. Concurrent/older uploads cannot overwrite a newer catalog. No Kai task execution automation is created.

Runtime files are installed under %USERPROFILE%/.research-compass/catalog-sync. Credentials are stored separately in %USERPROFILE%/.research-compass/cloud-catalog-sync.xml using Windows DPAPI for the current Windows user. The listener reuses that connection; credentials are never checked into source or sent to the browser. The hosted sync route requires both Sites private service access and its own CODEX_SYNC_SECRET runtime secret. Local sync-status.json and refresh-listener-status.json files record counts, times, and failures without credentials or chat contents.

To run once, invoke Sync-ResearchCompass.ps1 from its installed directory. Install or update the manual-refresh listener with scripts/local-sync/Install-RefreshListener.ps1 after deploying the matching Site protocol. To pause manual requests, disable the Manual refresh listener task; the hourly sync is independent. To revoke both helpers, remove CODEX_SYNC_SECRET in Sites and deploy the saved version, and disable both tasks. The app's project/task records continue working independently of catalog refresh.

Computer-off refresh: this helper reads local Codex project definitions and explicit chat membership, so it cannot obtain changes while that source computer is off. The saved hosted catalog remains available. A cloud scheduler would still need a supported cloud-accessible source for the same Codex project identities; none was verified in the November 10 investigation. Distinct ChatGPT projects are not substituted for local Codex projects.
